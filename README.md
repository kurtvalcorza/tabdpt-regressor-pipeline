# TabDPT Regressor Pipeline

DIMER-ready inference pipeline for **TabDPT v1.2 (TabDPT-Turbo)**, an open-weight tabular foundation model from Layer 6 AI for in-context supervised learning.

## What this repository provides

- supervised tabular **regression** with `TabDPTRegressor`;
- train-fitted preprocessing for mixed numeric/categorical CSV tables;
- immutable upstream weight provenance and SHA-256 verification;
- a DIMER manifest plus executable local/on-prem runtime adapter;
- deterministic validation splitting and support-row capping from DIMER runtime controls;
- a DIMER Notebook Specification 3.0 **standalone** `E2E` tutorial (generated by `tools/build_notebook.py`; see [`tutorials/README.md`](tutorials/README.md)) with a verified no-refit artifact reload and a closing external-artifact section, plus CI tests that do not download the 254 MB model in routine CI.

The weight bytes are not committed to this repository. Runtime acquisition is pinned to the immutable Hugging Face revision and verified before model construction. The local snapshot layout is `weights/tabdpt-1.2/` (the `MODEL_KEY`): the committed `dimer-base-manifest.json` there lists the checkpoint's path, byte size and SHA-256, `stage_missing_files` fetches only what is absent at the pinned revision, `verify_snapshot` re-hashes every entry, and `TabDPTRegressionPipeline.from_pretrained(weights_dir=...)` pins the verified file as the base checkpoint (see [`weights/README.md`](weights/README.md)).

## DIMER runtime contract

DIMER's current tabular transport is reused rather than inventing a new channel:

- `datasetPreprocessing` → `DIMER_PREPROCESSING_ARGS_JSON`
- `modelFinetuning` → `DIMER_HYPERPARAMETERS_JSON`

For TabDPT, `modelFinetuning` is a compatibility transport namespace only. `fine_tune` must remain `false`; the other fields control ICL context/inference (`n_ensembles`, `context_size`, `batch_size`, `seed`). Every manifest key is consumed by `tabdpt_regressor_pipeline.dimer_runtime`, and CI checks the manifest/runtime key sets for exact equality.

`dimer_entrypoint.py` reads `DIMER_DATASET_DIR`, accepts `train.csv` plus optional `val.csv` directly or inside one ZIP, applies the requested validation split/support cap, executes TabDPT, and writes `result.json`, `training_context.parquet`, and `artifact.json` under the configured output paths.

## Quick start

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e '.[model]'
```

```python
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split
from tabdpt_regressor_pipeline import TabDPTRegressionPipeline

frame = load_diabetes(as_frame=True).frame
train, test = train_test_split(frame, test_size=0.2, random_state=42)
pipe = TabDPTRegressionPipeline()
pipe.fit(train, target_column='target')
print(pipe.evaluate(test))
```

For DIMER, mount/cache the verified base weight through `DIMER_BASE_MODEL_PATH` so execution does not depend on live internet access.

`tutorials/tabdpt_regressor_colab.ipynb` (`E2E`) is declared under DIMER Notebook Specification 3.0 and is **standalone** (§4): generated by `tools/build_notebook.py`, it carries the package's three modules verbatim (the generator disables `dimer_runtime.py`'s `__main__` guard), the model identity, the snapshot manifest digests and the exact `pyproject.toml` runtime pins, so the exported notebook runs without this repository (parity enforced by `tests/test_notebook_parity.py` and `tools/validate_release_assets.py`). The E2E default path loads scikit-learn's bundled diabetes table (no download), validates it with `validate_inputs` into an input manifest, splits it, compares `training_mean_baseline`, conditions the model, writes an `evaluation_report` (`sample-sanity`: MAE / RMSE / R² on one seeded holdout), scores new rows with continuous point predictions, exports JSON/CSV plus the DIMER serving artifact (a directory and a deterministic ZIP of it), and reloads it across a fresh boundary without refitting preprocessing. Its closing external-artifact section (Section 10, NOTEBOOK_SPEC 3.0 §19.1) replaced the separate artifact-inference companion notebook (KND11): it downloads the pinned sample artifact — the release asset `sample-artifact-diabetes-v1` (v1: packed on the VM after a recorded hosted T4 run of this notebook's default path at `1e816d9`; the export stage's own in-run ZIP reproduced it byte for byte in the hosted runs at `c61b0f0` and `b869ab5`, so it meets SART9 by identity (owner ruling, 2026-10-22); a mutable release with a recorded SART7 deviation) and accepted only at its pinned SHA-256, never this run's export — extracts exactly `artifact.json` and `training_context.parquet`, validates it and its data contract before reconstruction, rebuilds serving state without refitting, and writes predictions for eight diabetes holdout rows to `outputs/external_artifact/`. Your own artifact ZIP (with its digest) and your own unlabelled rows are optional branches, off by default. BYOD is optional and gated off by default. ## Evaluation caveat

TabDPT was pretrained on real-world tabular datasets. Public tutorial/benchmark datasets may overlap directly or indirectly with upstream pretraining. Tutorial metrics are plumbing/sanity checks, not clean evidence of out-of-distribution quality.
